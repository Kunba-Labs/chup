September 15, 2026. Installed: **Chup! 1.0 (5)** at `/Applications/Chup!.app`. This closes the independently executable slice of increment 8. It does **not** certify the app for public release. The manual checklist is [MANUAL-TESTS.md](MANUAL-TESTS.md).

## Delivered

- Streaming export of an entire meeting to separate microphone, remote and assistant PCM16/24 kHz WAV files. All tracks start at meeting time zero; pauses and missing intervals remain silence. A manifest records source chunk intervals. No private-question journals are included. Export uses bounded one-second windows, exclusive destinations, cancellation and staged publication. RIFF limits are checked before writing; files beyond the approximately 24.8-hour per-track limit need a future RF64/split-file path.
- Encrypted per-leg waveform/timing indexes, generated by streaming authenticated audio records. Reopening reuses valid indexes; adding/changing audio invalidates them, and damaged derived caches rebuild. Playback still authenticates the audio itself. Waveform peaks are quarter-second envelopes, not word timestamps or proof of microphone health.
- Meeting search now searches stored transcript text and My notes as well as metadata. Transcript hits open the corresponding source. Private thoughts and assistant exchanges are excluded from shared-meeting search.
- Explicit keyboard access to the dark floating rail through the menu bar and a rebindable Focus floating controls action. Fresh presets use Control–Option–R. Existing saved assignments are preserved, so add the binding yourself if needed. Tab/arrows move between controls; Escape dismisses. Only explicit keyboard access makes the nonactivating panel eligible for key input; hover does not. Dictation from this path captures the destination before focusing the panel.
- Audio journals refuse to overwrite existing chunks; record size/format checks run before encoding/allocation. Durable file publication synchronizes contents and parent directories. The backend refuses to silently replace a missing journal encryption key. Usage estimates reject invalid/negative/nonfinite units and rates.
- Settings → Advanced exports allowlisted diagnostics: versions, permission states and counts. No audio, names, text, paths, endpoints, device identifiers or credentials are serialized, and no report is uploaded.
- A repeatable real-provider smoke runner using synthetic English/Dutch speech and isolated backend storage. Production API secrets remain in the trusted host environment.
- A Developer ID release packaging script, signed DMG, dependency notices, checksums and a manifest that explicitly records notarization status. An optional named Keychain profile supports submission/stapling/assessment; it does not submit by default. No driver is installed or included.

## Still requires engineering or external setup

These are **not** items a manual smoke test can magically complete:

1. **Private-input guarantees:** HAL polling every 100 ms cannot prevent another application switching to the physical microphone between checks. The optional route remains a prototype; platform mute coordination or a qualified controlled capture arrangement and measured failure behavior are still required. Use private text for real confidential material.
2. **Driver distribution and speakers:** choose a compatible license/distribution model for the BlackHole-derived component, implement and qualify signed installation/update/removal, and implement/calibrate speaker AEC. Ordinary recording is independent of all of this. The app's main DMG excludes the driver.
3. **Transcript intelligence:** stable acoustic speaker linkage across independent chunks and semantic reconciliation of materially different overlap text need further implementation and representative evaluation. Manual rename/split/merge and enrolled references already exist; independent `Speaker A` labels are not identities.
4. **Production services and delivery:** deploy a trusted authenticated backend with operational key management; enforce one backend process per journal directory until cross-process locking is implemented; configure modality-aware price accounting/invoice reconciliation. Optional sync and a separately named meeting bot remain separate features.
5. **Public release:** supply/configure the intended notary Keychain profile and distribution identity/channel; complete fresh-Mac Gatekeeper qualification. Auto-update signing/feed/hosting and the sandbox/App Store route remain unimplemented. The present unsandboxed AX/process-audio app and separate driver cannot be declared App Store-ready from this packaging work.
6. Hardware tests below may reveal additional implementation work: cross-device drift, helper-process capture, callback performance, permission transitions and physical playback are not qualified by offline rendering.

Developer ID packaging follows Apple's [notarization workflow](https://developer.apple.com/documentation/security/customizing-the-notarization-workflow). A Developer ID signature alone is not notarization or App Store acceptance.
