# Iteration 7 — privacy, recovery and setup

Implemented September 14, 2026. The product is now **Chup!** (including the exclamation mark). The built product is `Chup!.app`. On September 15, the rename was completed across the `Chup` project/scheme, `ChupCore` module, `com.chup.mac` bundle/Keychain service, `Application Support/Chup` data directory, backend configuration and `ChupMic2ch_UID` driver identity. No legacy branding or identity fallback is retained; there are no existing recordings to migrate. The optional public driver display name is **Chup! Mic**.

## Delivered

- Five-step native onboarding: welcome, workflow selection, relevant permissions, privacy/startup choices and ready. Setup can be deferred and reopened in Settings → General. No recording begins during setup, hover or launch.
- Settings → Permissions shows current OS checks, feature explanations, direct Privacy pane links, manual navigation instructions and refresh on returning to the app. Microphone, Accessibility and Input Monitoring requests are explicit. System-audio-only permission is truthfully shown as checked during actual capture; the optional ScreenCaptureKit route requests broader Screen & System Audio Recording access but saves audio only. It does not share screens or record video.
- Settings → General has launch at login through `SMAppService.mainApp`, actual registration/approval state, failure feedback and the official Login Items settings action. Registration is opt-in and does not depend on keeping Settings open.
- SQLCipher encrypts metadata, FTS, notes, revisions, receipts, request bodies and usage. A separate Keychain key protects the database; audio/reference encryption remains independent. Existing plaintext databases migrate through a verified encrypted sibling and atomic replacement. Committed WAL content is checkpointed first. Incorrect/missing keys fail closed. An app-level file lock serializes encrypted database opens. Old OS snapshots and external backups are not erased by migration.
- Retention schedules for meetings, dictation and private question audio default to “until I delete.” Changes require confirmation. Cleanup runs hourly while the app is open and idle. A meeting deletion cascades into notes/private thoughts, transcripts, summaries, actions, recording legs, enrolled references and request records. Durable plans resume interrupted deletions; tombstones reject late meeting writes. Removing a voice reference also removes saved upload requests using it across meetings.
- Readable meeting JSON export excludes private thoughts and assistant history by default; a separate explicit export includes them. Password-protected `.chupbackup` folders include an encrypted database snapshot, audio/reference files and wrapped recovery keys. PBKDF2-HMAC-SHA256 (600,000 rounds, random salt) derives the AES-GCM archive key; files stream in authenticated 1 MiB chunks. Verification restores into disposable storage. Activation restores to a new directory, verifies database integrity, rebases paths and selects it on the next launch; the current workspace is preserved. Backup passwords are not stored.
- Native HTTP requests commit their scope, body, hash and stable ID before networking; results and provider usage commit before use. Interrupted requests appear in Settings → Recovery. Saved results work offline. Summary recovery checks the current transcript fingerprint; assistant recovery creates a reviewable proposal, never an automatic note write, paste or voice session. Completed audio/cleanup request bodies are removed to avoid retaining duplicate audio and selected text.
- The trusted development backend has an authenticated, encrypted request/step journal. Completed provider steps replay without a second call. If a crash leaves provider acceptance uncertain, automatic replay stops with an explicit unconfirmed-result error. Starting a new attempt is a distinct user action that may incur another charge. Deletion queues send only opaque request IDs; the backend strips cached content and keeps minimal replay-prevention tombstones. Cache retention is 30 days by default, checked at startup and hourly.
- Settings → Usage separates file/live transcription, voice and backend response usage. Provider snapshots are upserted by stable ID; a late partial snapshot cannot replace a final one. Raw provider usage is retained. User-entered model rates produce estimates only when sufficient confirmed units exist; there are no invented prices or costs.

## Remaining limits and iteration 8

This is a buildable development preview. Actual signed TCC requests/revocation and launch-at-login behavior have not been exercised. No real provider credentials, conference capture, driver installation, physical privacy/broadcast qualification, acoustic echo cancellation, two-hour hardware soak or distribution signing was performed. Large real workspace migration and power-loss/disk-full backup testing remain release checks.

Usage is provider-reported accounting plus configurable estimates, not reconciliation with an account invoice. Mixed audio/text token pricing, missing final events, provider-side retention, organization cost APIs and billing exports still need account-level qualification. Raw units remain available; an incomplete session stays unconfirmed. WebSocket sessions are not replayed after a crash. Recovery retains file/cleanup responses for inspection; the existing transcript job workflow owns chunk application. Reading a saved summary can create a new summary version, with user overrides preserved.

The backend journal is designed for one process on one trusted host; its filesystem key must be protected and backed up separately. It is not a distributed exactly-once service. Deleting app/backend caches cannot erase provider records, exported copies or system backups. JSON export and full encrypted backups are implemented; standalone whole-meeting WAV export remains backlog.

One planned product increment remains: **8 — qualification and distribution**, with real engineering work as well as tests. Optional calendar/platform bots, cloud sync, wake phrases and open conversation remain in scope as later capabilities.
