## Shortcut implementation choice

Ordinary chords now use native Carbon `RegisterEventHotKey` with exclusive registration and pressed/released callbacks. Fn, modifier-only holds and side mouse buttons use a separate native event tap, with a common resolver for arbitration. KeyboardShortcuts was considered; native Carbon avoids adding a dependency while supporting registration failure reporting. Fn/mouse monitoring does not suppress system actions. Internal and known conflicts are checked; exhaustive cross-app conflict detection is not claimed.

The file transcription guide was rechecked for this increment: diarization references use `known_speaker_names[]` and `known_speaker_references[]`, up to four references of 2–10 seconds, encoded as audio data URLs. The backend validates its narrower mono 24 kHz PCM16 WAV contract before constructing multipart requests. See [official file transcription documentation](https://developers.openai.com/api/docs/guides/speech-to-text).

## Iterations 4–6 protocol and routing checks

Rechecked the official [Live guide](https://developers.openai.com/api/docs/guides/live), [delegation guide](https://developers.openai.com/api/docs/guides/live-delegation) and [Live WebSocket guide](https://developers.openai.com/api/docs/guides/voice-websockets?api=live). Native input control includes event IDs and waits for correlated `session.input_audio.muted` / `session.input_audio.unmuted` events with `client_event_id`. The app supplies silent PCM while muted. Delegation metadata is not the question; the controller waits for addressed text and acknowledged input completion. A localhost fixture verifies these code paths, not actual provider behavior.

Inspected the installed Apple SDK Core Audio headers for `kAudioProcessPropertyDevices`, `kAudioProcessPropertyIsRunningInput` and `kAudioStreamTerminalTypeHeadphones`. These are used as conservative route evidence. Polling these properties cannot atomically block another application changing its input; production privacy requires qualification beyond metadata checks. The separate [Apple driver sample](https://developer.apple.com/documentation/coreaudio/creating-an-audio-server-driver-plug-in) and [BlackHole source/license](https://github.com/ExistentialAudio/BlackHole) informed the prototype, with the pinned source and installation limitations recorded in DriverPrototype/README.md.
