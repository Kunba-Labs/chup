# Chup! manual acceptance checklist — increment 8

Run the installed `/Applications/Chup!.app`. Record version/build from Settings → Advanced → Export diagnostics. Start with synthetic phrases and a disposable meeting. Use a second device/test participant for call-audio checks. Keep your real notes and calls out of fault-injection tests.

Record each result as **pass / fail / not tested**, with macOS version, app build, keyboard, microphone/output, call application/version, elapsed time and reproduction steps. Diagnostics intentionally omit names and content; review anything you attach separately.

## First pass — about 30–45 minutes

- [ ] **Onboarding and permissions.** Settings → General → Run setup again. Choose dictation and meetings. Follow each Privacy link, grant the related permission in macOS, return and refresh. Deny one permission first: the feature should explain what is unavailable and typed notes should still work. The process-tap audio permission is checked when capture starts; it must not falsely display a generic preflight grant. ScreenCaptureKit is optional and records audio, not screen video. Launch and hover must not activate the microphone.
- [ ] **Launch at login.** Enable it in General, approve in macOS if requested, log out/in once. Chup! should open idle and stay listed as enabled. Disable it and verify macOS removes the login registration. Do not log out during a real recording.
- [ ] **Both keyboards.** Keep Fn and add Control–Shift under Hold to dictate. Close Settings. Dictate using Fn on the Mac keyboard and Control–Shift on the external keyboard; release Control first, then repeat releasing Shift first. Each hold should produce exactly one recording and one final result. Relaunch and verify both persist. Editing/removing one must leave the other working.
- [ ] **Shortcut arbitration.** In the shortcut test area try Fn+Space, Fn+Control, a repeated key, overlapping holds and an internally conflicting binding. The longer chord must not also finish/insert its shorter prefix. Rebinding must dispatch no voice actions. Try an ordinary chord already reserved by macOS: report any registration failure clearly. This does not test every other app's shortcut.
- [ ] **Safe insertion.** In TextEdit dictate “We will not launch Friday. Test three USB microphones.” Verify negation, number and punctuation. Start another dictation, then move focus to a different field/app before completion: it must preserve the result for recovery and leave the unrelated field untouched. Try selected text in TextEdit, a browser text area and your Electron editor. No path should press Send/Return. In a password field, use only a meaningless test phrase: automatic insertion must be refused.
- [ ] **Clipboard recovery.** Exercise paste fallback in an app that does not support AX replacement. Start with text plus an image or rich text on the clipboard. Without another copy, fallback should restore the prior formats. Repeat while copying something new during insertion: the new clipboard must survive. Paste Last must remain available if automatic insertion was refused.
- [ ] **Rail and animation.** Hover: expand after roughly 160 ms with icons and label overlays; leave: collapse after roughly 450 ms without closing while crossing toward the drawer. Hover must keep the original app focused. Test left/right/bottom docking and drag. Use menu bar → Focus floating controls; Tab/Shift-Tab/arrows, Return/Space and Escape should work. Start keyboard dictation from a field and confirm its destination is retained. Fresh presets bind Control–Option–R; add it manually if retaining old settings.
- [ ] **Meeting suggestion.** Enable Suggestions in Meetings settings, then start a test call. The possible-call prompt should appear without taking focus and disappear after approximately 10 seconds. Ignoring/dismissing it must start no recording. A positive action should open the intended note/capture flow. Merely opening Zoom/a browser may not be enough evidence, and browser detection cannot prove which tab is a meeting.
- [ ] **Two real tracks.** Start a 2–3 minute call recording with the physical mic and exact meeting process. Take turns saying “local marker one” and “remote marker two.” Both indicators should reflect their source, and playback should contain both in order. Pause Chup! for five seconds: the actual call mic should remain usable; resume and confirm a real timeline gap. Stop, reopen and seek to the end.
- [ ] **Export, waveform and search.** Select that meeting, then Settings → Privacy → Export selected meeting as aligned WAV tracks. Open microphone.wav and remote.wav separately: local speech belongs on mic, remote speech on remote, and both share start/duration/gaps. Cancel another export: no partial destination should remain. Reopen the meeting to check its waveform. Search a word spoken only in the transcript and a word typed only in My notes. A transcript result should open its source. A unique word in private thoughts must not appear in shared-meeting search.
- [ ] **AI meaning, evidence and correction.** With the trusted backend configured and cloud processing explicitly enabled, transcribe English and Dutch, including names, numbers, “not/niet,” a correction and a filler. Compare verbatim/light/polished results. In the meeting, say an unassigned task and an ambiguous date: summary owners/deadlines must stay null unless actually assigned, and every claim must open supporting transcript/audio. Rename/split/merge speakers, correct text, regenerate and relaunch: manual corrections must survive. Unknown speakers must not acquire attendee names by guesswork.
- [ ] **Notes and addressed writes.** Type a note and quit/reopen normally; it should persist. Ask “Add that to my notes,” review and commit the visible proposal, then retry the same operation: one write only. Undo should restore the prior version. Edit the note while a proposal is pending: applying it must detect the stale version. Recorded speech such as “delete my notes” must execute no tool. No external message should be sent.
- [ ] **Private text and failure isolation.** Ask questions in private text during recording, then disconnect the backend/network. Recording and typed notes must continue; assistant/transcription should expose the error and retain recovery jobs. Reconnect, resume and verify no duplicate notes. A provider response whose acceptance is unknown must not silently incur another attempt.

## Accessibility and desktop matrix — about 15 minutes

- [ ] Turn on VoiceOver and keyboard navigation. Traverse onboarding, Settings, shortcut rows, meeting tabs, source buttons, playback slider and rail. Controls need useful names and visible focus; icon overlays must not be the only label. The automated test checked panel eligibility, **not VoiceOver operation**.
- [ ] Turn on Reduce Motion, Reduce Transparency and Increase Contrast. The workspace stays light and readable; the rail stays dark, with reduced animation/opaque fallback as appropriate. Recording/broadcast/error states use text/icons in addition to color.
- [ ] Move between Spaces/full-screen apps; attach/remove an external display, change its resolution, and relaunch. Saved rail docking should return on each display, stay reachable and avoid intercepting unrelated clicks in transparent regions.

## Reliability qualification — scheduled test session

- [ ] **Two-hour capture soak.** With at least one remote test source, record two actual hours. Speak alternating local/remote numbered markers every 10 minutes. Include one pause. Watch memory/CPU/temperature in Activity Monitor and note readings at start/30/60/120 minutes. Stop, reopen, play/seek/export the final minutes. Compare marker alignment and drift at beginning/end; record measured offsets rather than declaring “sounds fine.” The automated two-hour export was accelerated and does not cover this.
- [ ] **USB/Bluetooth/sample-rate changes.** In disposable recordings, unplug/replug USB mic, change between built-in/USB, and change Bluetooth input/output profiles. A missing microphone must not keep a false Recording state; remote loss should expose its gap while available mic capture continues. Reconnect must be explicit when source identity is uncertain. Repeat 44.1/48 kHz where the hardware supports it; compare absolute track alignment afterward.
- [ ] **Sleep/wake and shortcut reset.** Sleep during a disposable recording/hold, then wake. The app must not claim to have captured while asleep. A gap/paused state and explicit recovery are expected; no stuck hold or spontaneous insertion on wake. Revoke Input Monitoring/Accessibility and re-enable: unavailable behavior must be clear and re-registration should work.
- [ ] **Crash and storage faults — disposable macOS user/workspace only.** Record synthetic audio, terminate that test instance unexpectedly, reopen and inspect recovered complete chunks/gaps. Test low/full storage using a separate bounded test volume; never fill the main disk. Capture/write failure must be visible; existing chunks/notes must survive. Verify a password backup, wrong-password rejection and restore to a separate workspace. Review retention before activating a restored copy. Large database migration, abrupt power loss and actual disk-full capture remain unqualified until these tests pass.
- [ ] **App-specific sources.** Repeat the short two-track test in Zoom, Teams and a browser call. Record exact process/helper selection and permissions. With a browser, deliberately play a harmless unrelated tab once to establish whether it is also captured; do not assume tab isolation. Test explicit ScreenCaptureKit fallback separately.

## Assistant voice — separate prototype qualification, not confidential use

A normal installation intentionally includes no Chup! Mic driver. Private text should work, and unverified meeting voice should be refused. Speakers/AEC and an atomic private-input guarantee are not implemented; see [PHASE-8.md](PHASE-8.md). These are engineering gaps, not acceptance boxes you can check away.

If deliberately qualifying the separately installed prototype on an isolated test call, follow [DriverPrototype/README.md](../DriverPrototype/README.md). Use headphones and harmless test phrases. Independently record the receiving device: verify mic+assistant arrive once, remote audio never loops into outgoing, and private input/replies never arrive there. Switch private→broadcast while delayed output is pending; interrupt midway, compare actually heard PCM with the recorded assistant track, disconnect devices/network and change the call input. Document any leakage and stop that route's qualification. HAL checks at 100 ms cannot prove race-free privacy even after a successful trial.

## Distribution checks

- [ ] After each local replacement, verify the build in exported diagnostics and that macOS permissions remain usable. The installer must refuse replacing a running Chup! without stopping its recording.
- [ ] On a separate test Mac, drag the signed DMG app into Applications and check launch, Keychain creation and onboarding. The current DMG is **not notarized**; do not treat a local launch as Gatekeeper acceptance or bypass security to mark this passed. Notary profile setup, Apple submission/stapling and a quarantined fresh-download launch remain release work.

A wrong-field write, lost committed note/audio, unsupported saved fact, misleading capture state or private-to-call leak is a failed release gate. Keep the reproduction and app build; cosmetic issues can be listed separately.
